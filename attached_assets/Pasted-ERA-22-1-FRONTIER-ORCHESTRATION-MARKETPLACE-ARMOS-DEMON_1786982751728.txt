3. RESPONSIBILITY BOUNDARIES

These boundaries are important.

OpenAI

OpenAI acts as the TC-S frontier orchestrator.

Responsibilities:

● understand marketplace/user intent

● discover available capabilities

● determine whether Replicator is appropriate

● normalize mission intent

● select/request an appropriate replication capability

● initiate the ArmOS workflow

● monitor mission state

● interpret returned status

● present results to the marketplace

● coordinate approval requirements

● coordinate future routing between inference providers

OpenAI must NOT fabricate manufacturing results.

It must never invent:

● geometry hashes

● fabrication completion

● inspection results

● tolerances achieved

● machine-code references

● part provenance

● assembly success

● Replication Complete status

Those must originate from ArmOS/Replicator.

Gemini 3 / ArmOS

Gemini 3 remains ArmOS’s specialist intelligence for:

● manufacturing inference

● engineering interpretation where currently implemented

● machine/part reasoning

● visual perception

● part identification

● spatial reasoning

● assembly assistance

● inspection/vision analysis

ArmOS remains authoritative for execution state.

13. MODEL-INDEPENDENT UIM PRINCIPLE

Do not make the Creation Capsule dependent upon either OpenAI or Gemini.

The capsule is a UIM/Replicator protocol artifact.

Conceptually:

```text
MODEL
  ↓
UIM
  ↓
CREATION CAPSULE
  ↓
EXECUTION
```

not:

```text
OPENAI CAPSULE
```

or:

```text

```

This distinction is critical.

Models provide inference.

UIM defines capability.

The Creation Capsule defines execution.

The ledger/provenance system records what happened.
