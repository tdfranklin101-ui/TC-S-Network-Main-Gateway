You are working on the TC-S Network Platform / Solar Economy Marketplace.

Goal:
Upgrade the existing platform so TC-S is clearly structured as a marketplace-first, energy-denominated economy — NOT a fiat exchange service. Fiat payments and verified REC contributions are value-onramps used to activate Solar balances inside a defined marketplace. Solar is designed to circulate through goods, services, digital products, agent commissions, and community commerce. Cash settlement must be optional, disabled by default, and only available if specifically enabled by a commissioned network.

Do not remove any existing working functionality unless required for this upgrade. Preserve all current database tables, wallet logic, marketplace logic, agent logic, and ledger functionality. Add migration-safe changes only.

------------------------------------------------------------
1. CORE COMPLIANCE / PRODUCT POSITIONING RULES
------------------------------------------------------------

Implement the following system-wide design rules:

A. TC-S is NOT a fiat exchange service.
B. Fiat and REC inputs are value-onramps into the Solar marketplace economy.
C. Solar is an internal energy-denominated unit of account for marketplace activity.
D. Solar is intended primarily for internal circulation, not external redemption.
E. Cash settlement is optional, disabled by default, and configurable per commissioned network.
F. Each commissioned network may choose one of these settlement modes:
   - "disabled"
   - "admin_approved"
   - "limited"
   - "compliant_partner"
G. If settlement is disabled, no cash-out/settlement UI should appear for members.
H. If settlement is enabled, use cautious language:
   “Eligible balances may be submitted for settlement under this network’s rules, subject to identity verification, reserve status, platform terms, and applicable law.”
I. Never display language like:
   “Cash out anytime”
   “Guaranteed redemption”
   “Convert Solar back to dollars whenever you want”
   “Solar is redeemable on demand”
J. Platform fees should be described as marketplace, activation, commission, licensing, or administrative settlement fees — not exchange spreads.

Add these rules as comments/constants in a central config file if one exists. If not, create a file:

/lib/compliancePolicy.ts

Export a compliance policy object containing:
- platformClassification
- solarPurpose
- fiatPurpose
- recPurpose
- settlementDefault
- prohibitedPhrases
- approvedSettlementDisclaimer
- approvedMarketplaceDescription
